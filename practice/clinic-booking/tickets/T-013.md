# T-013: Today screen shows tomorrow's appointments after about 8pm

**Status:** Open  **Type:** Bug  **Severity:** S3 workaround exists  **Priority:** Medium  **Reporter:** Emma (reception)

> In the evening, after about 8pm, the Today screen starts showing tomorrow's appointments instead of today's. Mornings look fine.

## 1. Summary
After 20:00 clinic time, the Today screen (`GET /appointments/today`) lists tomorrow's appointments for reception. This happens when the server runs with `CLINIC_TIMEZONE=UTC` and not with the default `America/New_York`.

## 2. Environment
- Build / commit: `9e54b5b`
- Where: both. The Today screen calls `GET /appointments/today` (`app/routes.py:195`).
- Config: suspected `CLINIC_TIMEZONE=UTC` on the clinic machine (unconfirmed). Default in `app/config.py:4` and `.env.example` is `America/New_York`.
- Clock: any weekday from 20:00 New York time (EDT, UTC-4), which is 00:00 UTC the next day. In winter (EST, UTC-5) it would start at 19:00.

## 3. Steps to reproduce
Frozen-clock script in the scratchpad (`repro_t013.py`), real app code, `DB_PATH=:memory:`:
1. Set the clock to Tue 2026-10-13 10:00 New York time.
2. Book doctor 1 / patient 1 at `2026-10-13T16:00:00-04:00` and at `2026-10-14T09:00:00-04:00` (`tests/helpers.book()`).
3. Move the clock to Tue 19:59 New York time, then to Tue 20:30 New York time, and call `GET /appointments/today` each time.
4. Run the script once with `CLINIC_TIMEZONE=America/New_York` and once with `CLINIC_TIMEZONE=UTC`.

## 4. Actual behaviour
With `CLINIC_TIMEZONE=America/New_York` (default): correct at every time.
```
now=Tue 10:00 NY: /appointments/today -> ['2026-10-13T20:00:00Z']
now=Tue 19:59 NY: /appointments/today -> ['2026-10-13T20:00:00Z']
now=Tue 20:30 NY: /appointments/today -> ['2026-10-13T20:00:00Z']
```
With `CLINIC_TIMEZONE=UTC`: `/health` returns `{"status": "ok", "timezone": "UTC"}`. Tuesday's list is empty all day. At 20:30 it shows Wednesday's 09:00 visit.
```
book Tue 16:00 NY: 422 Outside working hours (08:00-17:00)
now=Tue 10:00 NY: /appointments/today -> []
now=Tue 19:59 NY: /appointments/today -> []
now=Tue 20:30 NY: /appointments/today -> ['2026-10-14T13:00:00Z']
```
The UI header still shows Tuesday, because `CLINIC_TZ` is hard-coded to `America/New_York` (`app/static/index.html:480`). The list under it is Wednesday's.

## 5. Expected behaviour
- Today lists the appointments whose New York date is today, at any hour. Rule: "Clinic time is America/New_York … All hours below are clinic time." (`docs/business-rules.md:6`)

## 6. Analysis
- **Asks:** Make the evening Today list show today's appointments again.
- **Ambiguous:** We have not seen the clinic machine's config. UTC is the only setting we found that reproduces the report, and Emma's "about 8pm" matches UTC midnight in EDT.
- **Root cause:** Suspected config: `CLINIC_TIMEZONE=UTC` in the deployed `.env`. The code is correct. `app/routes.py:202` converts "now" with `scheduling.to_local()` (the T-004 fix, `06dc744`), and `tests/test_booking.py:302` `test_today_uses_clinic_date_late_in_the_evening` covers it and passes. With UTC, every clinic-time check (`app/scheduling.py:11`) is shifted by 4 hours. Booking hours are wrong too: a valid 16:00 NY slot is rejected.
- **Bug type:** config (suspected; same symptom as T-004, which was a code bug and is fixed)
