# T-014: Don't let patients book a doctor who is away or a day the clinic is closed

**Status:** In Review  **Type:** Feature  **Priority:** Medium  **Reporter:** Tung Mai (dev)  **Estimate:** M

## 1. Summary
Today every weekday is bookable for every doctor, so reception can book visits on public holidays and on days a
doctor is on leave. Add clinic holidays (the whole clinic is closed) and doctor time off (one doctor is away for a
date range). Slots, booking and rescheduling respect both. No new dependency: both persist in SQLite next to appointments.

## 2. Analysis
- **Asks:** Admins can close the clinic on a day and block a doctor's days off; nobody can book into them.
- **Ambiguous:** Whole days or part days, who manages them, and what happens to appointments already on a newly closed day (see §8).
- **First step:** Tests that a holiday has no slots and rejects a booking, then the same for one doctor's time off.

## 3. Approach
- `app/models.py` → `Holiday(date, name)`, `TimeOffIn(start_date, end_date, reason)`, `TimeOff(id, doctor_id, ...)`.
- `app/store.py` → `holidays` and `time_off` tables (time-off ids from SQLite `AUTOINCREMENT`, under the write lock, so never duplicated or reused) (`CREATE TABLE IF NOT EXISTS`, JSON blob like appointments),
  loaded on start, written through by `save_holiday`/`delete_holiday`/`save_time_off`/`delete_time_off`, cleared by `reset()`.
- `app/scheduling.py` → `closed_reason(doctor_id, day)` (weekend, holiday, time off; clinic-local day).
  `free_slots` returns `[]` when it is set; `check_day_open` raises 422 for clinic closures and 409 for time off.
- `app/routes.py` → `check_day_open` on booking and reschedule; `closed` reason on the slots response;
  `GET/POST /holidays`, `DELETE /holidays/{date}`, `GET/POST /doctors/{id}/time-off`, `DELETE /doctors/{id}/time-off/{id}`.
  Writes need the admin token. Closing a day that holds active appointments is a 409 listing their ids.
- `app/static/index.html` → the Book screen's empty state shows the server's `closed` reason.
- No change to the stored `Appointment` shape, so no migration.

## 4. Acceptance criteria
- AC-1 Given a holiday on a weekday, when any doctor's slots are requested for it, then there are none and `closed` names the holiday.
- AC-2 Given a holiday, when someone books or reschedules into it, then the API returns 422.
- AC-3 Given time off for doctor 1, when doctor 1 is booked on a day in the range (both ends included), then 409; doctor 2 is still bookable.
- AC-4 Given an active appointment on a day, when an admin adds a holiday or that doctor's time off over it, then 409 naming the appointment. Cancelled appointments don't block.
- AC-5 Adding or removing a holiday or time off without the admin token returns 403.
- AC-6 Removing a holiday or time off reopens the day.
- AC-7 Holidays and time off survive a restart.
- AC-8 `pytest` passes with no existing test weakened.

## 5. Out of scope
- Part-day time off (a doctor away for the afternoon only).
- A web page for managing holidays and time off (Swagger with the admin token for now).
- Recurring holidays, and per-doctor working hours.

## 6. Business-rule impact
New "Holidays and time off" section in `docs/business-rules.md`, marked as dev defaults pending clinic manager confirmation.

## 7. Test plan
- Automated: `tests/test_closures.py` (18 tests covering AC-1 to AC-7).
- Manual: in `/docs`, add a holiday and a doctor's time off with the admin token, then on the Book screen pick that
  doctor and day: no slots, and the reason is shown.

## 8. Open questions
1. Is blocking whole days enough, or do doctors need part-day time off? (clinic manager)
2. Is refusing to close a day that already has appointments right, or should the system cancel them free of charge and notify the patients? (clinic manager)
3. Should reception, not only admins, manage time off? (clinic manager)
4. An old appointment that was never completed or marked no-show still counts as active, so it blocks a holiday or time off on that past date (409). Acceptable, or should past dates ignore it? (clinic manager)
