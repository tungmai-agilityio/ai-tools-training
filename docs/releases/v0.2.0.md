# v0.2.0

Second release. Sprint S-003 goal: pull requests cannot merge without a passing, always-reported CI check; production deploys only after an approved GitHub Actions run that verifies the result; and rollback is one tested step. The release also ships the Revenue screen.

## Fixes
- #118 Stop the push-guard hook from blocking commands that only mention "git" and "push" in text
- `/health` reports the running commit, so a deploy or rollback can be verified

## Deploy notes
- Production redeploys only through the `Deploy Production` workflow: `render.yaml` sets `autoDeploy: false` for `clinic-booking`. Dispatch it from `main` and pass the release tag; the job targets the `production` environment, so its required reviewer approves before any step runs.
- `production` environment: required reviewer, secret `RENDER_DEPLOY_HOOK_URL`, variable `APP_URL`, deployment branch policy `main`.
- Rollback: the `Rollback` workflow takes an `environment` and a previous `ref`. `production-rollback` needs no reviewer and holds its own copy of `RENDER_DEPLOY_HOOK_URL` and `APP_URL`, branch policy `develop`; `staging` keeps its `develop` policy with its own secret and variable, and drops the required reviewer.
- `tests` must report on every pull request, including docs-only ones. Squash merge only, linear history; the maintainer bypass needs a green `/review-pr` and `gh pr checks`.
- No app data migration. SQLite on Render free resets on every deploy (ADR-0005).
- `.env.example` now documents `DEMO_SEED` (staging only) and `RENDER_GIT_COMMIT` (set by Render). Leave both unset locally.
