# S-003: Deployment safety and CI gates

**Status:** Planned  **Start:** 2026-11-16  **End:** 2026-11-20  **Milestone:** none

## Goal
Pull requests cannot merge without a passing, always-reported CI check; production deploys only after an approved GitHub Actions run that verifies the result; and rollback is one tested step. Proposed 2026-10-29 by the maintainer.

## Scope
T-036 (required CI and merge settings), T-034 (approval-gated production deploy), T-035 (rollback and rehearsal), T-037 (push-guard hook false positive). Decisions: ADR-0005.

Dependencies and parallel sessions (one session, one branch, one PR per ticket; only dependent work waits):

| Wave | Tickets | Starts when | Notes |
|---|---|---|---|
| 1 | T-036 required CI, squash merge, bypass, AI re-review, `claude.yml` lockdown | day 1 | Unblocks every later PR. Part of it is GitHub settings applied by the maintainer. |
| 2 | T-034 production deploy, T-037 hook fix | T-036 merged (T-037 may start day 1) | Two parallel sessions. T-034 needs the `RENDER_API_KEY` secret and variables in the `production` environment. |
| 3 | T-035 rollback and staging rehearsal | T-034 merged | Reuses T-034's secrets, variables and polling code. |

## Out of scope
Monitoring, alerts and metrics reports, a second reviewer, making the AI review a required check, durable data or paid hosting (ADR-0005), approval-gate hooks (`plans/features/hooks-approval-gates`).

## Capacity
One maintainer plus up to two parallel dev sessions in wave 2; each ticket needs a human review or bypass-merge by the maintainer. Estimates: T-036 S, T-034 S, T-035 S, T-037 XS. No hours were given, so capacity is judged by parallelism and review, not hours.

## Risks
- T-036 changes the rules every later PR merges under; apply the GitHub settings last, once the workflow change is merged, or PRs will wait on a check that does not report.
- T-034 and T-035 depend on Render's API behaviour (deploy trigger, deploy list, rollback), which is confirmed only at plan time.
- The `staging` and `production` environments have reviewer settings that must match the tickets before any workflow uses them.
- Free-tier cold starts make deploy and health checks slow; timeouts need to cover them.
