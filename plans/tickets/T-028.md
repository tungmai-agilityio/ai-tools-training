# Deploy a free test site on Render

**Type:** Chore  **Priority:** Medium  **Estimate:** S  **Push:** Draft
**Areas:** api, docs  **Depends on:** T-019, T-021 (login, admin seed, `ADMIN_TOKEN` removed); ADR-0005 accepted

## 1. Description
Claude in Chrome needs a public HTTPS URL to test the app and its Secure cookie. Host it on Render's free tier (ADR-0005). The admin seed and `AUTH_SECRET` already come from the auth tickets; this ticket adds the demo-data switch and the deploy doc.

## 2. Constraints
- No new dependency; SQLite stays. No secrets or credentials in the repo.
- `DB_PATH=/tmp/clinic.db` on the host; data resets on restart.

## 3. Acceptance criteria
- AC-1 Given `DEMO_SEED=1` and an empty database, when the app starts, then the demo doctors, patients and appointments exist (same data as `scripts/seed_demo.py`).
- AC-2 Given `DEMO_SEED` unset or not `1`, then no demo data is added.
- AC-2b The demo seed creates no login accounts (only doctors, patients and appointments), runs only at startup, is never exposed over HTTP, and uses fake data only.
- AC-3 Given a restart on a database that already has data, then the demo data is not duplicated.
- AC-4 `docs/deploy-render.md` matches the final env var names, has no `ADMIN_TOKEN`, and says how to generate `AUTH_SECRET` (`openssl rand -hex 32`).
- AC-4b Given `AUTH_SECRET` unset or shorter than 32 characters, when the app starts, then it refuses to start (confirm T-019 covers this; add it there if not).
- AC-5 A human deploys per the doc, and Claude in Chrome signs in as the seeded admin over HTTPS.
- AC-6 `pytest` passes with no existing test weakened.

## 4. Out of scope
Postgres, persistent volumes, custom domain, `render.yaml` (add only if Tung asks).
