# Require login and roles on all clinic endpoints

**Sprint:** S-002  **Feature:** authentication  **Type:** Feature  **Priority:** High  **Estimate:** M  **Push:** Ready  **Plan:** Approved
**Areas:** api  **Decisions:** ADR-0001, ADR-0002, ADR-0003

## 1. Description
Working Artifacts (BA/QA edit there): [spec and test cases](https://claude.ai/artifact/Vx4CrGK2SRXTmfFyVShedS), [UI design](https://claude.ai/artifact/VaAYYy7WoVCPzw2wEwS6jp).

Every clinic endpoint requires a valid session cookie. Staff can book and run the appointment lifecycle; admin-only endpoints require the admin role. The shared `X-Admin-Token` is removed. Depends on T-019; can be built in parallel with T-020.

## 2. Business rules
Staff: bookings and lifecycle. Admin: also holidays, time off, delete appointment, revenue report. Public: `/health`, `/`, `/static/*`, `/docs`, `POST /auth/login`.

## 3. Constraints
- Add the response header `Content-Security-Policy: script-src 'self'; object-src 'none'; base-uri 'self'` and reject POST, PATCH, PUT and DELETE requests whose `Origin` header is present and does not match the host (CSRF second layer behind `SameSite=Strict`).
- Replace `require_admin` and the per-route `x_admin_token` checks (`app/routes.py:69`, `:145`, `:156`, `:182`, `:194`, `:418`, `:435`) with the role dependency.
- Existing tests keep their intent; they gain a login helper. `scripts/seed_demo.py` logs in.
- `ADMIN_TOKEN` is removed entirely, not deprecated. Remove it from: `app/config.py`, `app/routes.py` (`require_admin` and every `x_admin_token` parameter), `app/static/index.html` (the admin-token field on Revenue), `.env.example`, `README.md`, `CLAUDE.md`, `REVIEW.md`, `.github/workflows/security.yml`, `docs/references/code-conventions.md`, `docs/business-rules.md` (the two "admin token" phrases) and the tests that set `config.ADMIN_TOKEN` (`tests/test_booking.py`, `test_closures.py`, `test_reports.py`, `test_ui_browser.py`, `test_frontend.py`).

## 4. Acceptance criteria
- AC-1 Given no or an invalid session, when calling any protected route, then `401`.
- AC-2 Given a staff session, when booking, checking in, completing, cancelling, rescheduling, then behaviour is unchanged.
- AC-3 Given a staff session, when calling a holiday, time-off, delete-appointment or revenue-report route, then `403`.
- AC-4 Given an admin session, then all of the above work.
- AC-5 Given the old `X-Admin-Token` header alone, then `401`; the `Authorization` header is ignored too.
- AC-6 Public routes remain reachable without a session.
- AC-6b Given a session cookie and a POST whose `Origin` is another site, then `403` and nothing changes; a POST with no `Origin`, or with the clinic's own origin, works.
- AC-6c Every response carries `Content-Security-Policy: script-src 'self'; object-src 'none'; base-uri 'self'`.
- AC-6d Given the repository after this ticket, then no file under `app/`, `scripts/`, `tests/`, `.env.example` or the docs mentions `ADMIN_TOKEN` or `X-Admin-Token`, except records that describe its removal; a test fails if one reappears in `app/`, `scripts/` or `.env.example`.
- AC-7 `pytest` passes with no existing test weakened.
