# Browser-test login, sign-out and roles with the session cookie

**Type:** Chore  **Priority:** Medium  **Estimate:** S  **Push:** Ready
**Areas:** tests  **Decisions:** ADR-0004

> Claude-assisted draft for Tung to edit. Belongs with the authentication feature (T-022); renumber or fold into T-022 if preferred.

## Why
The auth UI relies on an `HttpOnly` cookie, a CSRF check and a script-only CSP. Unit tests can't prove the browser sends the cookie, the UI sends the CSRF header, or staff never see admin controls.

## What
- Fixtures `staff_page` and `admin_page`: create fake users in the store and sign in with `context.request.post("/auth/login")`, which shares the page's cookie jar. Never write tokens to storage or inject cookies by hand.
- One test per role signs in through the login form.
- Browser tests for T-022's UI test cases: login form only when signed out, sign-out returns to login, staff menu hides admin items, a write with a missing or wrong CSRF token is refused for every state-changing method, the session cookie has `HttpOnly` and `SameSite=Strict`, no credential in `localStorage`/`sessionStorage`.
- Screenshots (T-025) with empty or masked password fields: the login screen, signed-in header and user-management panel.

## Done when
- [ ] T-022's UI test cases each map to a browser test or a stated manual step.
- [ ] Screenshots are uploaded to the auth UI-design Artifact "As built" section.

## Acceptance criteria and test cases
Depends on T-024, T-025 and the auth API (T-019, T-020, T-023).

**Acceptance criteria**
- AC-1 `staff_page` and `admin_page` fixtures sign in through `context.request.post("/auth/login")`; no cookie or token is injected by hand.
- AC-2 One test per role signs in through the login form.
- AC-3 Browser tests cover: login form only when signed out, sign-out returns to login, staff menu hides admin items, missing/wrong CSRF refused on every state-changing method, cookie `HttpOnly` and `SameSite=Strict`, no credential in `localStorage`/`sessionStorage`.
- AC-4 Screenshots (masked passwords) of the login screen, signed-in header and user-management panel.

**Test cases**
| ID | AC | Given | When | Then |
|---|---|---|---|---|
| TC-1 | AC-1 | staff and admin users | fixtures run | page is signed in via the cookie jar |
| TC-2 | AC-2 | each role | form login | role-specific UI shown |
| TC-3 | AC-3 | staff signed in | open menu | no admin items |
| TC-4 | AC-3 | signed in | POST/PUT/PATCH/DELETE without or with wrong CSRF | refused |
| TC-5 | AC-3 | signed in | inspect cookie and storage | HttpOnly, SameSite=Strict, no credential in storage |
| TC-6 | AC-4 | each screen | `snap()` | PNGs exist, password fields masked |
