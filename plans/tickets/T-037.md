# Stop the push-guard hook from blocking commands that only mention "git" and "push" in text

**Sprint:** S-003  **Type:** Chore  **Priority:** Low  **Estimate:** XS  **Push:** Ready  **Plan:** Pending
**Areas:** tooling

## 1. Description
`.claude/hooks/block-forbidden-command.py` fails closed when it cannot parse a command: it applies the pattern `\bgit\b.*\bpush\b` with DOTALL to the whole text. A command with an unbalanced apostrophe (for example a heredoc with "maintainer's") that contains `git` anywhere and the word `push` anywhere, even in prose, is blocked with "could not parse this git push". Reproduced: `git status; echo it's done and push later` is blocked; `echo it's a note: push a commit` passes.

## 2. Business rules
None. Guardrail only; real enforcement is branch protection.

## 3. Constraints
- Stay fail-closed for anything that really looks like a push: a line that starts a `git` command and contains `push` must still block when unparseable.
- No new dependency. Do not weaken the other rules in the hook.

## 4. Acceptance criteria
- AC-1 Given an unparseable command whose `git` and `push` are on different lines and not in one command, then the hook allows it.
- AC-2 Given an unparseable command with a line such as `git push --force origin x`, then the hook still blocks it.
- AC-3 Given any parseable command, then behaviour is unchanged.

## 6. Out of scope

## 7. Open questions
- Proposed pattern: `^\s*(?:\S+=\S+\s+)*git\b[^\n]*\bpush\b`, per line. Confirm at plan time that it cannot be bypassed by a quote that spans lines (`sh -c "git\npush"`).
