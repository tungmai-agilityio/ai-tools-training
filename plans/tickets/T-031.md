# Read-only CI failure triage comment on the PR

**Sprint:** S-002  **Type:** Chore  **Priority:** Low  **Estimate:** S  **Push:** Ready
**Areas:** ci  **Plan:** Pending
Source: [hooks-approval-gates plan](../features/hooks-approval-gates/plan.md), C2.

## 1. Description
When the `Tests` workflow fails on a PR, a Claude job reads the log and posts one comment saying whether the failure looks flaky or real, the likely cause and the next step. It is the lesson's "start read-only" step: it never changes code, labels or runs. Do this after T-030, so CI is stable and fast first.

## 2. Constraints
- New `.github/workflows/ci-triage.yml`, triggered by `workflow_run` of `Tests` with conclusion `failure`, using `anthropics/claude-code-action@v1` and the existing `CLAUDE_CODE_OAUTH_TOKEN`.
- Permissions: `contents: read`, `actions: read`, `pull-requests: write` only. No label, push or re-run permission.
- The log is untrusted input: the job treats it as data and never follows instructions inside it. No secrets printed.
- A `workflow_run` job runs with base-branch workflow code; it must not check out or run code from the failing PR.

## 3. Acceptance criteria
- AC-1 Given a failed `Tests` run on a PR, when triage finishes, then exactly one comment is posted (updated on re-run, not duplicated) with: flaky or real, likely cause, next step.
- AC-2 Given a passing run, then triage does not run.
- AC-3 The workflow requests only the permissions above; it cannot push, label or merge.
- AC-4 Verified once on a deliberately failing branch; the evidence is in the PR.
- AC-5 Triage is advisory: it does not change the PR's required checks or the merge rules.

## 4. Out of scope
Auto-fix, re-running flaky jobs, labels, deploy or rollback tooling (revisit after ADR-0005 is accepted).
