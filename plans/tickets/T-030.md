# Cut the CI test run below 5 minutes

**Type:** Chore  **Priority:** Medium  **Estimate:** M  **Push:** Draft
**Areas:** ci  **Plan:** Pending
Source: [hooks-approval-gates plan](../features/hooks-approval-gates/plan.md), C1.

## 1. Description
The `Tests` workflow (`.github/workflows/tests.yml`) took 11m33s on a cold run against a 5 minute target. Find where the time goes (pip install, Chromium and system dependencies, the browser UI tests) and cut it without dropping coverage.

## 2. Constraints
- No test is skipped, weakened or removed to gain time. UI tests keep running on every PR to `develop`.
- No new dependency or paid runner. Fake data only; no secrets added.

## 3. Acceptance criteria
- AC-1 A written breakdown of step timings from a recent cold and warm run is in the PR description.
- AC-2 Given a cold run (empty caches), when the workflow finishes, then total time is under 5 minutes, measured on three runs and reported in the PR.
- AC-3 A warm run is not slower than before.
- AC-4 Screenshots are still uploaded as the `screenshots` artifact; `REQUIRE_BROWSER=1` is kept.
- AC-5 `pytest` passes locally and in CI with the same number of tests as before.

## 4. Out of scope
Deploy automation, new workflows (T-031), changing test content.
