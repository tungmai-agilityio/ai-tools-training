# Hook allows the project's requirements install and names the route to approval

**Sprint:** S-002  **Type:** Chore  **Priority:** Medium  **Estimate:** S  **Push:** Ready
**Areas:** tooling  **Plan:** Pending
Source: [hooks-approval-gates plan](../features/hooks-approval-gates/plan.md), H1, H2.

## 1. Description
`.claude/hooks/block-forbidden-command.py` only denies. The exact installs `-r requirements.txt` and `-r requirements-dev.txt` pass today only through the permission classifier, which prompted us. Let the hook return an explicit `allow` for them, and make every deny message say how to get approval, as the "Hooks as approval gates" lesson recommends.

## 2. Constraints
- Allow only when the whole command is exactly that install (optionally `python -m pip`). Any other segment, chaining, comment or expansion falls through to the existing checks.
- No new dependency; stdlib only. Existing deny rules and exit code 2 behaviour stay.
- Allow is JSON on stdout (`hookSpecificOutput.permissionDecision: "allow"` with a reason), exit 0.

## 3. Acceptance criteria
- AC-1 Given `pip install -r requirements.txt` or `-r requirements-dev.txt` (also `python -m pip ...`), when the hook runs, then it prints an allow decision and exits 0.
- AC-2 Given an install of any other package, or the requirements install chained with another command (`;`, `&&`, `|`), when the hook runs, then no allow is printed and the existing result is unchanged (exit 2 for the install, normal pass-through for the chain without a forbidden part).
- AC-3 Given any denied command, when the hook blocks it, then stderr states the rule and the route to approval (for example "ask a maintainer / change the ticket"), still exit 2.
- AC-4 `tests/test_push_hook.py` covers AC-1 to AC-3 and its existing cases still pass; no test is weakened.
- AC-5 A command whose text only mentions the install (a heredoc or quoted string) is not allowed by AC-1 and keeps today's behaviour.

## 4. Out of scope
Ask-on-push, GitHub write gates, test or migration edit gates, protecting hook files, a decision log (see the plan, "Revisit later").
