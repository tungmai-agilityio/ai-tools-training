# Let users change their password and admins reset it

**Sprint:** S-002  **Feature:** authentication  **Type:** Feature  **Priority:** High  **Estimate:** S  **Push:** Ready  **Plan:** Approved
**Areas:** api  **Decisions:** ADR-0002, DDR-0002

## 1. Description
Working Artifacts (BA/QA edit there): [spec and test cases](https://claude.ai/artifact/Vx4CrGK2SRXTmfFyVShedS), [UI design](https://claude.ai/artifact/VaAYYy7WoVCPzw2wEwS6jp).

A signed-in user can change their own password. An admin can reset any user's password and receives a temporary password once; that user must change it at next login. Depends on T-019 and T-020 (users); can run in parallel with T-021.

## 2. Business rules
See `plans/features/authentication/spec.md` §5 (approved by Tung as client, 2026-10-27): change needs the current password; new password follows the account rules and differs from the current one; reset gives a one-time temporary password and forces a change; either clears the lockout and ends the user's other sessions.

## 3. Constraints
- No new dependency. Temporary password from `secrets`, never logged or stored in clear. Passwords never returned except the one-time temporary one.

## 4. Acceptance criteria
- AC-1 Given a signed-in user, when `POST /auth/change-password` with the right current password and a valid new one, then `204`; the new password logs in and the old one does not.
- AC-2 Given a wrong current password, then `403` and nothing changes.
- AC-3 Given a new password that is too short or equal to the current one, then `422`.
- AC-4 Given an admin, when `POST /users/{id}/reset-password`, then `200` with a temporary password shown once; a staff session gets `403`.
- AC-5 Given a user with a temporary password, when logging in, then the response has `must_change_password: true` and every other route except change-password and `/auth/me` answers `403` until the password is changed.
- AC-6 Given a change or reset, then older sessions for that user stop working (`session_version` is bumped; the user who just changed their password gets a fresh cookie) and the lockout is cleared.
- AC-7 `pytest` passes with no existing test weakened.

## 6. Out of scope
Email reset links, password history, MFA.

## 7. Open questions
None. Decided: a change or reset ends the user's other sessions.
