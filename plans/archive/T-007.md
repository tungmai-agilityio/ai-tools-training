# T-007: Slot times are wrong on my machine

**Status:** Done  **Type:** Bug  **Severity:** S3 workaround exists  **Priority:** Medium  **Reporter:** New developer (Ryan)

> I cloned the repo and ran it. The doctor's first slot shows up at 4am for me,
> but it is 8am on Emma's screen. All the tests pass on my laptop, so I think it
> is a frontend problem?

## 1. Summary
The default `CLINIC_TIMEZONE` was `UTC`, so a fresh clone with no `.env` generated slots four hours early. It was a config default, not a frontend bug.

## 2. Environment
- Build / commit: fix `1554dda`, merged in `a48d5fa`.
- Where: API and UI — slot generation on a fresh clone.
- Config: `CLINIC_TIMEZONE` unset.
- Clock: any.

## 3. Steps to reproduce
1. Clone the repo and do not create `.env`.
2. Start the server.
3. Open the Book screen and look at the first slot.

## 4. Actual behaviour
- The first slot was 04:00 instead of 08:00 clinic time.
- The test suite passed because it runs with the timezone set.

## 5. Expected behaviour
Rule: "The clinic is in New York. Clinic time is America/New_York … All hours below are clinic time." (`docs/business-rules.md`)
- AC-1 Given a fresh clone with no `.env`, when the server starts, then the first slot is 08:00 clinic time.

## 6. Analysis
- **Asks:** Make a fresh clone show clinic time without extra setup.
- **Ambiguous:** The report blamed the frontend, but the frontend already used a fixed clinic time zone.
- **Root cause:** `app/config.py` defaulted `CLINIC_TIMEZONE` to `"UTC"`; tests set the value, so they could not catch the default (`1554dda`).
- **Bug type:** config

## 7. Clarifying questions
None recorded. The default was visible in `app/config.py`.

## 8. Fix and test
- Regression test: `tests/test_scheduling.py::test_clinic_timezone_defaults_to_new_york`.
- Fix: default `CLINIC_TIMEZONE` to `America/New_York` and record it in `.env.example`.
