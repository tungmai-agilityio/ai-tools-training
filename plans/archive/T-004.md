# T-004: Today's schedule screen shows tomorrow's patients in the evening

**Status:** Done  **Type:** Bug  **Severity:** S3 workaround exists  **Priority:** Low  **Reporter:** Emma (reception)

> When I stay late to close up, the "today" list suddenly shows tomorrow's
> patients, or goes empty. In the morning it is fine. Our screen worked OK last month.

## 1. Summary
`GET /appointments/today` used the UTC date, so from 20:00 New York time (00:00 UTC) the Today screen listed tomorrow's appointments.

## 2. Environment
- Build / commit: fix `06dc744`, merged in `c4780f9`.
- Where: UI and API — Today screen (`GET /appointments/today`).
- Config: default `America/New_York`.
- Clock: from 20:00 clinic time in summer (19:00 in winter).

## 3. Steps to reproduce
1. Freeze the clock at Tue 2026-10-13 20:30 New York time.
2. Book one appointment on Tuesday and one on Wednesday.
3. Open the Today screen.

## 4. Actual behaviour
- The list showed Wednesday's appointment while the header still said Tuesday.

## 5. Expected behaviour
Rule: "The clinic is in New York. Clinic time is America/New_York … All hours below are clinic time." (`docs/business-rules.md`)
- AC-1 Given 20:30 New York time, when Today is opened, then only Tuesday's appointments are listed.

## 6. Analysis
- **Asks:** Keep the Today list on the clinic's date late in the evening.
- **Ambiguous:** The report gave no time, build, or time-zone setting.
- **Root cause:** `app/routes.py` used `clock.now_utc().date()` instead of `scheduling.to_local(clock.now_utc()).date()` (`06dc744`).
- **Bug type:** code

A later report of the same symptom with `CLINIC_TIMEZONE=UTC` is T-013 (config, still Open).

## 7. Clarifying questions
None recorded. The evening timing in the report was enough to reproduce.

## 8. Fix and test
- Regression test: `tests/test_booking.py::test_today_uses_clinic_date_late_in_the_evening`. It fails before `06dc744` and passes after.
- Fix: convert "now" to clinic time before taking the date.
