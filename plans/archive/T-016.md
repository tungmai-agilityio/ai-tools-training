# T-016: Revenue report screen for the clinic manager

**Status:** Done  **Type:** Feature  **Priority:** Medium  **Reporter:** Tung Mai (dev)  **Estimate:** S

## 1. Summary
The revenue report (T-015) can only be read through Swagger by pasting the admin token. Add a "Revenue" screen to the
single-page UI where the manager enters the admin token and a date range and reads consultation, penalty and total
revenue per doctor and per day. Frontend only: no backend change, no new dependency, no charts.

## 2. Analysis
- **Asks:** A Revenue screen that calls `GET /reports/revenue` and shows the totals, the per-doctor rows and the per-day rows.
- **Ambiguous:** Nothing material is left. The token handling, default range and chart scope were decided with the requester (§3); the three T-015 §11 business questions stay open and do not change the UI mechanics.
- **First step:** Add the nav item and an empty `#revenue` screen, then wire the request with the token header.

## 3. Approach
Decisions (requester, 2026-10-21): the admin token is held in memory only; the default range is the current month; tables only.

- `app/static/index.html` only:
  - Nav: a fourth link "Revenue" after "Today" (`:353-357`), always visible (the server is the real gate).
  - A `<section id="screen-revenue" hidden>` following the `screen-appointments` pattern (`:425`): a password field "Admin token", `From` and `To` date inputs, a "Run report" button, and a results area with `aria-live="polite"`.
  - Add `"revenue"` to `SCREENS` (`:569`). `route()` (`:570`) does not call the API on entry; the defaults are filled once.
  - Token: a module-level variable. Never `localStorage`/`sessionStorage`, the URL or the hash; a reload clears it. A 403 clears the variable and the field and shows a re-enter message.
  - Default range: `From` = first day of the current month, `To` = `todayKey()` (`:522`), so "today" is in clinic time. Use string slicing on the key, not `new Date(...)`.
  - `api()` (`:543-556`): `fetch(path, { headers: <default>, ...opts })` lets `opts.headers` replace the Content-Type default. Change it to `const { headers, ...rest } = opts;` and `fetch(path, { ...rest, headers: { ...(opts.body ? { "Content-Type": "application/json" } : {}), ...headers } })`. Also throw errors with the status: `Object.assign(new Error(...), { status: res.status })`. No existing caller passes `headers`, and they only read `e.message`, so they are unaffected. Callers pass headers as a plain object.
  - Form: a `<form>` with a `<button type="submit">` and `preventDefault()` (Enter works in any field and the in-memory token survives). Token input `type="password" autocomplete="new-password"` (browsers ignore `off` on password fields).
  - Stale responses: a `revSeq` counter like `slotSeq` (`:653`); ignore a response if a newer run started.
  - Validation: a top-level `revenueRangeError(from, to)` using `keyDate()` (`:517`): both dates present, `from <= to` (string compare), and `(keyDate(to) - keyDate(from)) / 864e5 < 366` (matches `app/routes.py:177`).
  - 403 (`e.status === 403`): clear the token variable, the field and the stored result, focus the token field, keep `From`/`To`, show `empty("Admin token not accepted", "Enter the admin token again.")`.
  - Errors: `empty()` does not escape, so pass constant titles and `esc(e.message)` as the hint; add a Retry button via the `empty()` action argument. No error toast: the inline state already shows the message.
  - Defaults are filled once in `init()` (`:928`), not in `route()`, so a user's entries are not overwritten. `From` = `todayKey().slice(0, 8) + "01"`, `To` = `todayKey()`.
  - Reuse existing classes (no new ones except one mobile rule): `.cb-pagehead`, `.cb-card`, `.cb-fields`/`.cb-field`/`.cb-input`, `.cb-btn--primary`, `.cb-stats`/`.cb-stat` for Consultation/Penalty/Total, `.cb-table` with `.cb-num`/`.cb-right`. Below 768px the table becomes cards without headers, so add `data-label` on money cells and one rule `.cb-table td[data-label]::before { content: attr(data-label); display: block; }` in that media block.
  - Render the server's numbers as given (`by_doctor`, `by_day`, `totals.total_cents`); do not re-sum them.
  - Rendering: `money()` (`:505`) for every amount, `fmtKey()` (`:521`, with the year, since a range can cross years) for day labels, `esc()` (`:500`) on doctor names, `empty()`/`skeleton()` (`:524-528`) for states. Build rows as strings, never from the response through `innerHTML` unescaped.
  - Show the run range and the time it ran above the results, plus a one-line note: amounts are gross, counted on the scheduled day in clinic time, and a deleted visit drops out.
  - Keep the last result for the session, labelled with its range. A new run replaces it; a 403 or error clears it.
- No change to `app/routes.py`, `app/models.py` or the tests' fixtures.

## 4. Acceptance criteria
- AC-1 Given the app is open, when I click "Revenue", then `#revenue` shows with the nav item marked current, `From` is the 1st of the current clinic month, `To` is today in clinic time, and no `/reports/revenue` request has been sent.
- AC-2 Given the token field is empty, when I click "Run report", then a message asks for the admin token and no request is sent.
- AC-3 Given a valid token and range, when I run the report, then the request is `GET /reports/revenue?from=…&to=…` with the header `X-Admin-Token`, and the grand totals, one row per doctor (including doctors with $0.00) and one row per day with money are shown.
- AC-4 Given the API returns `total_cents: 39997`, then the screen shows `$399.97`, and the per-doctor rows and per-day rows each add up to the grand total.
- AC-5 Given a 200 response with an empty `by_day`, then a "No revenue in this range" empty state shows, the doctors still list at $0.00, and it is not styled as an error.
- AC-6 Given a wrong or missing token (403), then an inline "Admin token not accepted" message shows, the token field is cleared, and no previous result stays visible.
- AC-7 Given `From` is after `To`, a range over 366 days, or a missing date, then the UI blocks the request or shows the server's 422 text, and the entered values are kept.
- AC-8 Given the server is unreachable or returns another error, then an error state with a retry shows, using the existing `api()` error message.
- AC-9 Given I enter a token and run the report, then the token is not in the URL or hash and is not in `localStorage` or `sessionStorage`; after a reload the field is empty.
- AC-10 Given a doctor name containing `<b>x</b>`, then it is shown as text, not as markup.
- AC-11 Given I leave the Revenue screen and come back in the same session, then the last result is still shown, labelled with its range and run time.
- AC-12 Given light and dark themes, then the screen is readable in both; the inputs have labels; keyboard users can run the report with Enter in any field.
- AC-13 Given `api()` is called with `opts.headers` and a JSON body, then both the caller's headers and `Content-Type` are sent, and the existing screens (book, list, today, cancel, reschedule) behave as before.
- AC-14 `pytest` passes with no existing test weakened.

## 5. Out of scope
- Charts, CSV/PDF export, patient-level reports.
- Any backend change, and any admin UI for delete, holidays or time off.
- Showing or hiding the nav item by role (the UI has no roles).
- Resolving the T-015 spec §11 questions (penalty as revenue, scheduled-day accounting, deleting completed visits).
- Remembering the token across reloads.

## 6. Business-rule impact
None. The screen displays what `docs/business-rules.md` "Revenue report" already defines. Add one line to `README.md` that the report has a UI at `#revenue`.
