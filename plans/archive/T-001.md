# T-001: Appointment list looks wrong

**Status:** Done  **Type:** Bug  **Severity:** S3 workaround exists  **Priority:** Medium  **Reporter:** Emma (reception)

> Hi, when I scroll through the appointment list in the back office some people
> show up twice. I think it is when there are a lot of appointments. Can you
> look? It is confusing for the nurses.
>
> Thanks!

## 1. Summary
The appointment list repeats the last row of a page at the top of the next page, so reception sees the same appointment twice.

## 2. Environment
- Build / commit: fix `fa3726f`, merged in `1b5901e`.
- Where: UI — Appointments list (`GET /appointments`).
- Config: default; not time-dependent.
- Clock: any.

## 3. Steps to reproduce
1. Log into the website.
2. Open the appointment list with 5 per page.
3. Scroll to the bottom of page 1 and note the last person.
4. Load page 2 (scroll or "next") and look at the first row.

## 4. Actual behaviour
- Page 1 returns 5 items.
- Page 2 returns 6 items, and its first item is the last item of page 1.

## 5. Expected behaviour
No business-rule line covers pagination; the contract is the list endpoint's `page_size`.
- AC-1 Given a page of appointments, when it is requested, then it returns exactly `page_size` rows, except the last page.
- AC-2 Given two consecutive pages, when they are loaded, then no appointment id appears on both.

## 6. Analysis
- **Asks:** Fix the appointment list so the same patient doesn't appear twice for reception.
- **Ambiguous:** There are no steps, no page or filter, no example appointment, and no clue whether "twice" means across pages or within one page.
- **Root cause:** The pagination slice used an off-by-one offset (`app/routes.py`, fixed in `fa3726f`), so the last row of each page was repeated at the start of the next.
- **Bug type:** code
