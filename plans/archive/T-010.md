# T-010: Reschedule from the web page

**Status:** Done  **Type:** Feature  **Priority:** Medium  **Reporter:** Emma (reception)  **Estimate:** S

> T-009 added `POST /appointments/{id}/reschedule`, but the web page has no button
> for it, so reception still has to use Swagger or cancel and rebook.

## 1. Summary
Add a Reschedule action to the Appointments tab for `scheduled` appointments. It reuses the Book tab's slot picker and calls the T-009 endpoint, so reception never has to leave the page.

## 2. Analysis
- **Asks:** A Reschedule action on the Appointments tab for `scheduled` appointments that calls the T-009 endpoint.
- **Ambiguous:** How the new time is picked, and whether the length can be changed from the page.
- **First step:** Reuse the Book tab's slot picker so the new time is always a real free slot in clinic time.

## 3. Approach
- Appointments tab: `scheduled` rows get a **Reschedule** button next to Check in / No-show / Cancel.
- Clicking it opens the Book tab in reschedule mode: doctor and patient fixed to the appointment's, length preset to its current 30/60 min (can be changed), date set to the appointment's day.
- The slot picker counts the appointment's own slot as free (`withOwnSlots`), matching the endpoint.
- Picking a free slot and pressing **Reschedule #N** calls the endpoint with `start` and `duration_minutes`.
- Success: toast with the new time and fee, back to normal booking mode. Failure (409/422): toast shows the API's `detail`.
- A **Back to booking** button leaves reschedule mode without changes.
- Change confined to `app/static/index.html`.

## 4. Acceptance criteria
- AC-1 Given a `scheduled` appointment, when the row is shown, then it has a Reschedule action.
- AC-2 Given Reschedule is chosen, then Book opens in reschedule mode with the appointment's doctor and patient locked, and its date and length preset.
- AC-3 The appointment's own current slot is offered as free.
- AC-4 Given a free slot and **Reschedule #N**, then the page calls `POST /appointments/{id}/reschedule` with `start` and `duration_minutes`.
- AC-5 Given a 2xx response, then a toast shows the new time and fee and the page returns to normal booking mode.
- AC-6 Given a 409 or 422, then a toast shows the API's `detail`.
- AC-7 Given **Back to booking**, then reschedule mode ends with no change.
- AC-8 `pytest` passes with no existing test weakened.

## 5. Out of scope
- Changing doctor (rules say cancel and rebook).
- Any API or business-rule change.
- Fee preview before confirming.

## 6. Business-rule impact
None. The feature only exposes the approved T-009 reschedule endpoint.

## 7. Test plan

- Manual: reschedule a visit from the Appointments tab, confirm the old slot is free, try a taken slot to see the 409 detail, then leave via **Back to booking**.
