# T-017: Booking page offers time slots that have already passed

**Status:** In Review  **Type:** Bug  **Severity:** S3 workaround exists  **Priority:** Low  **Reporter:** Tung Mai (dev, found while testing the booking feature)

> Booking page shows Wed 21 Oct with every slot free, but it was already the evening of
> Wed 21 Oct at the clinic. I could pick 8:00, press Confirm, and got "Could not book this slot".

## 1. Summary
`GET /doctors/{id}/slots` returns slots that have already started, so the Book page lets reception pick a time that `POST /appointments` then refuses with 422 "Appointment must be in the future".

## 2. Environment
- Build / commit: `827446e` (develop)
- Where: both. API `GET /doctors/{id}/slots`, shown on the Book screen
- Config: `CLINIC_TIMEZONE=America/New_York`
- Clock: Wed 2026-10-21 22:38 clinic time (Thu 22 Oct 09:38 in Saigon). Any day where some slots are already behind "now" shows it, including this morning's slots when reception books later the same day.

## 3. Steps to reproduce
1. Freeze the clock at Wed 2026-10-14 14:00 clinic time (`now["value"] = datetime(2026, 10, 14, 18, 0, tzinfo=timezone.utc)`).
2. `GET /doctors/1/slots?date=2026-10-14`.
3. `POST /appointments` for the first slot returned (`2026-10-14T12:00:00+00:00`, 08:00 clinic time).

## 4. Actual behaviour
- Step 2 returns 16 slots, starting at 08:00, six hours in the past.
- Step 3 returns `422 {"detail": "Appointment must be in the future"}`.
- In the browser: the past day opens with all 16 slots free and selectable; Confirm ends in the error toast.

## 5. Expected behaviour
`docs/business-rules.md`: "Booking must be in the future and no more than 60 days ahead." A slot the booking endpoint would refuse for being in the past must not be offered as free.
- AC-1 Given it is Wed 14:00 clinic time, when slots are requested for today, then only slots starting after 14:00 are returned (a slot starting exactly now is refused by booking, so it is not offered).
- AC-2 Given a clinic day that is already over, when slots are requested for it, then the list is empty.
- AC-3 Given a future day, when slots are requested, then all free slots are returned as before.

## 6. Analysis
- **Asks:** Stop offering slots that can no longer be booked.
- **Ambiguous:** Nothing material. The rule is explicit, and `validate_start()` already refuses `start <= now`.
- **Root cause:** `scheduling.free_slots()` (`app/scheduling.py:67`) builds the day's slots from working hours and removes only busy or lunch times. It never compares them with `clock.now_utc()`, so it disagrees with `validate_start()` (`app/scheduling.py:29`). `routes.doctor_slots()` (`app/routes.py:108`) is its only caller, and the Book page only renders what the API returns (`app/static/index.html:694`).
- **Bug type:** code

## 7. Clarifying questions
None.

## 8. Fix and test
- Failing tests (fail before, pass after): `tests/test_scheduling.py::test_slots_skip_times_that_have_already_passed` and `::test_a_day_that_is_over_has_no_slots`.
- Fix: `free_slots()` skips slots that are not after `clock.now_utc()`. The fix is on the server so every client benefits, and the page needs no change.
