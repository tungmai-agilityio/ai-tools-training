# T-015: Daily revenue report for the clinic manager

**Status:** In Review  **Type:** Feature  **Priority:** Medium  **Reporter:** Tung Mai (dev)  **Estimate:** S

## 1. Summary
There is no way to see what the clinic earned. Fees sit on each appointment (`fee_cents`, `cancellation_fee_cents`) and
only the paginated `GET /appointments` shows them. Add a read-only, admin-only report that sums money over a date
range, split into consultation revenue and penalty revenue, per doctor and per day. No new dependency and no change to
the stored `Appointment` shape.

## 2. Analysis
- **Asks:** For a date range, the manager sees total revenue in integer cents, per doctor and per day.
- **Ambiguous:** Whether penalty fees (no-show, late cancel) are revenue. Decided: reported separately (see §8).
- **First step:** A test that two completed appointments on one day sum correctly, then the timezone boundary test.

## 3. Approach
Full design: `plans/features/revenue-report/spec.md`.
- `app/models.py` (after `TimeOff`, ~line 60) → `RevenueTotals` (computed `total_cents`), `DoctorRevenue`, `DayRevenue`, `RevenueReport`.
- `app/routes.py` (new "Reports" section after `delete_appointment`, ~line 423) → `GET /reports/revenue` with
  `dependencies=[Depends(require_admin)]` (`:69`) so a missing token is 403 before date validation. Params `from_date`/`to_date`
  use `Query(alias="from"/"to")` like `doctor_slots` (`:108`). Day = `scheduling.to_local(a.start).date()` (`app/scheduling.py:15`), both ends inclusive.
  - `completed` → `fee_cents` to consultation; `no_show`/`cancelled` → `cancellation_fee_cents` to penalty; other statuses ignored.
  - 422 `DomainError` for `from` > `to` and a range over 366 days (same cap as `add_time_off`, `:181`). A zero-money appointment creates no `by_day` row.
  - `by_doctor` lists every doctor in `store.doctors` with zeros; totals are the sums over `by_doctor`.
- No stored-shape change, no migration, no frontend change, no ADR.

## 4. Acceptance criteria
- AC-1 Given two completed appointments for doctor 1 (an insured visit at 12000 and an uninsured one at 15000) on one clinic day, when an admin reports that day, then consultation is 27000 and doctor 1's consultation is 27000.
- AC-2 Given completed appointments for two doctors on two days, when reported, then each doctor and each day total is right and both breakdowns add up to the grand total.
- AC-3 Given `scheduled`, `checked_in` and `left_unseen` appointments in range, when reported, then none of their fees are counted.
- AC-4 Given a late-cancelled appointment (50%) and a no-show (100%), when reported, then both appear under penalty, not consultation. A free cancellation adds 0.
- AC-5 Given a completed appointment at 2026-10-14 23:00 New York time (2026-10-15 03:00 UTC), when reporting 2026-10-14 only, then it is included; reporting 2026-10-15 only excludes it.
- AC-6 Given a completed insured visit, then the discounted `fee_cents` is counted. Given a rescheduled-then-completed appointment, then its updated fee and new start day are used.
- AC-7 Given no matching appointments, then 200 with all totals 0, every doctor listed with 0, and empty `by_day`.
- AC-8 Given `from` after `to`, a missing or malformed date, or a range over 366 days, then 422.
- AC-9 Given no admin token or a wrong one, then 403.
- AC-10 The call changes no appointment or stored data.
- AC-11 `pytest` passes with no existing test weakened.

## 5. Out of scope
- A web page for the report (Swagger with the admin token for now; UI is a separate ticket).
- CSV/PDF export, patient-level reports, refunds, payments and invoicing.
- Reporting by completion or cancellation date (needs a stored timestamp and a migration).
- Any change to fee calculation.

## 6. Business-rule impact
New "Revenue report" section in `docs/business-rules.md`: consultation revenue = fee of completed visits; penalty revenue = no-show and late-cancel fees; days are scheduled start in clinic time; gross, no refunds; admin only. Dev defaults, pending clinic manager confirmation. The penalty lines inherit the T-005 pending confirmation.

## 7. Test plan
- Automated, all in new `tests/test_reports.py` (every test fails first: the route returns 404). Seed fees: D1 15000, D2 12997; P1 insured, P2 not.
  - AC-1 `test_two_completed_visits_on_one_day_sum_into_consultation` (D1+P1 12000 + D1+P2 15000 = 27000)
  - AC-2 `test_doctor_and_day_breakdowns_add_up_to_the_grand_total`
  - AC-3 `test_scheduled_checked_in_and_left_unseen_are_not_counted`
  - AC-4 `test_late_cancel_and_no_show_count_as_penalty_not_consultation`, `test_free_cancellation_adds_nothing_and_no_day_row`
  - AC-5 `test_late_evening_visit_counts_on_its_clinic_day`, `test_late_evening_visit_is_not_on_the_next_utc_day`
    (must use `store.save(Appointment(...))` at 2026-10-15T03:00Z: no bookable slot differs by date between UTC and clinic time)
  - AC-6 `test_insured_visit_counts_discounted_fee`, `test_rescheduled_visit_counts_new_fee_on_new_day`
  - AC-7 `test_empty_range_lists_every_doctor_with_zero`
  - AC-8 `test_from_after_to_is_rejected`, `test_missing_from_or_to_is_rejected`, `test_malformed_date_is_rejected`, `test_range_over_366_days_is_rejected`, `test_range_of_exactly_366_days_is_allowed`
  - AC-9 `test_report_needs_admin_token`, `test_report_refused_when_no_admin_token_configured`, `test_bad_token_gets_403_before_date_validation`
  - AC-10 `test_report_changes_no_stored_data` (assert 200 too, else it passes on 404)
- Edge-case checklist: insured/odd cents, 30 vs 60 min and back-to-back are covered above. N/A with reason: DST day (2026-11-01 is a Sunday), lunch, exactly-24h (fee fixed at cancel time, tested in `test_fees.py`), weekend, 60-day booking limit, restart (store loads from SQLite, `test_persistence.py`), UI parity (no UI).
- Manual: in `/docs`, authorize with the admin token, complete and no-show a few appointments, call `/reports/revenue` over the week.

## 8. Open questions
1. Are no-show and late-cancel fees really revenue, or only owed amounts until paid? Reported separately for now. (clinic manager)
2. Is the scheduled day acceptable for accounting, even for a late-cancel fee that arose on the cancellation day? (accounting)
3. Deleting a completed appointment (admin) removes it from past totals. Acceptable, or should deletion of completed visits be blocked? (clinic manager)
