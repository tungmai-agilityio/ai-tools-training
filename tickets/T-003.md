# T-003: Cancellation fee wrong sometimes

**Status:** Done  **Type:** Bug  **Severity:** S2 wrong money  **Priority:** Medium  **Reporter:** Accounting (Hannah)

> At month end the cancellation fees do not add up with what we calculate by hand.
> It is only a tiny difference, but accounting needs it to be exact. Some doctors
> seem affected, not all.
>
> Please check.

## 1. Summary
The late-cancellation fee rounded with `round()` instead of the project's integer half-up rule, so fees with odd cents were off by one for some doctors.

## 2. Environment
- Build / commit: fix `2afa7dd`, merged in `97a6637`.
- Where: API and accounting totals (`POST /appointments/{id}/cancel`).
- Config: default.
- Clock: inside the 24-hour cancellation window.

## 3. Steps to reproduce
Reconstructed from the regression test.
1. Pick a doctor whose base fee gives an odd cent at 50%.
2. Cancel a scheduled appointment less than 24 hours before its start.
3. Compare the charged fee with the hand calculation.

## 4. Actual behaviour
- The fee differed by one cent for some doctors; the error carried into the month-end total.

## 5. Expected behaviour
Rules: "Cancelling less than 24 hours before the start costs 50% of the consultation fee." and "All amounts in cents, percentages round half up." (`docs/business-rules.md`)
- AC-1 Given a 50% late-cancellation fee with odd cents, when it is calculated, then it rounds half up.

## 6. Analysis
- **Asks:** Fix the cancellation fees so that they are correct.
- **Ambiguous:** How the fee is calculated and what should happen when a fee is waived.
- **Root cause:** `fees.py` used `round(fee_cents * 0.5)` (banker's rounding on a float) instead of the integer helper `_percent(fee_cents, 50)` (`2afa7dd`).
- **Bug type:** code

## 7. Clarifying questions
1. Can you share one affected doctor and month with the system total, your hand-calculated total, and the difference?
2. Is the difference the same on every affected line, or only in the monthly total? If you can, list one or two individual cancellations that don't match.
3. What fee rule are you calculating by hand (flat or percentage, cutoff window, tax, exemptions), and where is it documented?

Answered by the regression test; kept for the record.

## 8. Fix and test
- Regression test: `tests/test_fees.py::test_late_cancellation_rounds_half_up_on_odd_cents`. It fails before `2afa7dd` and passes after.
- Fix: use `_percent(fee_cents, 50)` in `app/fees.py`.
