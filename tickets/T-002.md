# T-002: Doctor double booked

**Status:** Done  **Type:** Bug  **Severity:** S2 wrong data  **Priority:** High  **Reporter:** Dr. James Carter

> Yesterday I had two patients in my room at the same time. The system should
> not allow that. Please fix before Monday.
>
> *Comment from Emma:* it happened with the long visits I think.

## 1. Summary
The booking check accepted a second appointment whose start fell inside an existing long visit, so one doctor could have two patients at once.

## 2. Environment
- Build / commit: fix `9e055f3`, merged in `347a270`.
- Where: API — booking (`POST /appointments`).
- Config: default.
- Clock: not time-dependent.

## 3. Steps to reproduce
Reconstructed from the regression tests; the original report gave no date or ids.
1. Book a 60-minute visit for doctor 1 at 09:00.
2. Book another visit for doctor 1 at 09:30.

## 4. Actual behaviour
- The second booking was accepted, so both visits overlapped.

## 5. Expected behaviour
Rules: "A doctor cannot have two appointments that overlap in time." and "A patient cannot have two appointments that overlap in time, even with different doctors." (`docs/business-rules.md`)
- AC-1 Given a 60-minute visit, when another booking starts inside it for the same doctor, then the API returns 409.
- AC-2 Given a patient with a 60-minute visit, when they book an overlapping visit with another doctor, then the API returns 409.
- AC-3 Back-to-back visits remain allowed.

## 6. Analysis
- **Asks:** Fix the system so that doctors do not get double booked.
- **Ambiguous:** There is no specific date, time range, and no information about whether it is a recurring issue, and no details on what should happen if a double booking does occur.
- **Root cause:** `scheduling.overlaps()` only compared the new start with the existing end (`a_start <= b_start < a_end`) and ignored the new appointment's duration. A long existing visit was therefore invisible to a booking that started inside it (`9e055f3`).
- **Bug type:** code
