# T-006: Anyone can delete appointments

**Status:** Done  **Type:** Bug  **Severity:** S2 wrong data  **Priority:** High  **Reporter:** IT consultant

> During a test on the shared server I was able to remove an appointment without
> being an admin. Please lock this down. I did not capture the exact request.

## 1. Summary
`DELETE /appointments/{id}` ran without a valid admin token, and when `ADMIN_TOKEN` was unset the check was skipped entirely.

## 2. Environment
- Build / commit: fix `32d9efc`, merged in `7a1b3ce`.
- Where: API — `DELETE /appointments/{id}`.
- Config: `ADMIN_TOKEN` set and unset.
- Clock: not time-dependent.

## 3. Steps to reproduce
1. Start the server with and without `ADMIN_TOKEN`.
2. Call `DELETE /appointments/1` with no `X-Admin-Token` header.
3. Repeat with a wrong token.

## 4. Actual behaviour
- The appointment was deleted without a token, and all deletes were allowed when `ADMIN_TOKEN` was empty.

## 5. Expected behaviour
Rule: "Deleting an appointment is for administrators only and needs the admin token." (`docs/business-rules.md`)
- AC-1 Given no token or a wrong token, when delete is called, then the API returns 403.
- AC-2 Given `ADMIN_TOKEN` is unset, when delete is called, then the API fails closed with 403.
- AC-3 Given the correct token, when delete is called, then the appointment is removed.

## 6. Analysis
- **Asks:** Require the admin token to delete an appointment.
- **Ambiguous:** The reporter did not capture the request or the server's config.
- **Root cause:** `require_admin()` skipped the check when `config.ADMIN_TOKEN` was empty and compared tokens with `!=` instead of a constant-time comparison (`32d9efc`).
- **Bug type:** code

## 7. Clarifying questions
None recorded. The endpoint and the fail-open path were found by inspection.

## 8. Fix and test
- Regression test: `tests/test_booking.py::test_delete_is_refused_when_no_admin_token_is_configured`.
- Fix: fail closed when the token is unset and compare with `hmac.compare_digest`.
