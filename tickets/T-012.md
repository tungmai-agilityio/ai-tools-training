# T-012: Persist appointments across restarts

**Status:** Done  **Type:** Feature  **Priority:** Medium  **Reporter:** Tung Mai (dev)  **Estimate:** S

## 1. Summary
Appointments live only in the in-memory `store`, so every server restart wipes them. Persist them in SQLite
through Python's built-in `sqlite3` module, so there is no new dependency. Doctors and patients stay seed-only.

## 2. Analysis
- **Asks:** Appointments still exist after a restart. Booking, lifecycle, reschedule and delete keep their current behaviour.
- **Ambiguous:** This conflicts with CLAUDE.md's "Don't add a dependency or a database. The in-memory store is intentional."
  That rule has to be changed on purpose as part of this ticket (see §8).
- **First step:** Write `test_appointment_survives_restart`, which fails today, then add write-through to `Store`.

## 3. Approach
Keep the `Store` interface. The routes keep reading `store.appointments` (a dict of `Appointment`), and SQLite
works as a write-through backing file. Reads, conflict checks and `scheduling.py` don't change.

- **`app/config.py`:** `DB_PATH = os.getenv("DB_PATH", "data/clinic.db")`.
- **`app/store.py`:**
  - `Store(db_path=config.DB_PATH)`: open a connection with `check_same_thread=False`, then
    `CREATE TABLE IF NOT EXISTS appointments (id INTEGER PRIMARY KEY, data TEXT NOT NULL)`.
  - On load, read every row into the dict using `Appointment.model_validate_json`, and set `_next_id` to `max(id) + 1`.
  - `save(appt)` runs `INSERT OR REPLACE` with `appt.model_dump_json()` and commits.
  - `delete(id)` removes both the row and the dict entry.
  - `reset()`, used by tests and the seed, also runs `DELETE FROM appointments` and sets the id counter back to 1.
  - One shared connection with a `threading.Lock` around writes, because the sync routes run in FastAPI's threadpool.
    Add a `ponytail:` comment that names this ceiling.
  - Each row stores the appointment as one JSON blob, not one column per field. The model then has no schema
    to migrate, and the UTC-aware datetimes round-trip through pydantic.
- **`app/routes.py`:** call `store.save(appt)` before the return in every endpoint that changes data: create
  (in place of `store.appointments[appt.id] = appt`), check-in, complete, left-unseen, no-show, cancel and
  reschedule. Delete uses `store.delete(...)`. The save goes in the endpoint, not in `_move()`, so the fee
  changes made after `_move` in no-show and cancel are saved too.
- **`tests/conftest.py`:** `os.environ.setdefault("DB_PATH", ":memory:")`, so the existing tests run unchanged.

## 4. Acceptance criteria
- AC-1 Book an appointment, restart `uvicorn`, and `GET /appointments` still returns it with the same fields.
- AC-2 Status changes, fee changes (no-show, cancel), reschedule and admin delete are all still there after a restart.
- AC-3 After a restart, the next booking's id continues from the highest stored id.
- AC-4 `pytest` passes with no existing test weakened or changed, apart from the `DB_PATH` line in `conftest.py`.

## 5. Out of scope
- An ORM, migrations, or any new dependency.
- Persisting doctors and patients. They come from `data/seed.json` and the API never changes them.
- Any change to business rules or the API.

## 6. Housekeeping
- `.gitignore`: `data/*.db`. `.env.example`: `DB_PATH=data/clinic.db`.
- Remove "in-memory store" from the module docstring in `routes.py`.
